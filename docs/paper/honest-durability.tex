\begin{abstract}
Approximate nearest-neighbor (ANN) work usually reports recall and queries per
second but not whether an acknowledged insert survives failure. We make
durability a measured axis and implement an opt-in \emph{recall-bounded
committer} in a segmented C++20 HNSW store. The shipped default remains
durable-before-return. In weak mode, one leader serializes WAL appends and
admission, exposes complete records through an exact volatile tail, and hardens
that tail with versioned WAL fences. Monotone appended, visible, and durable
LSNs, reserved LSN high-water ranges, bounded WAL parsing, and a two-phase seal
make production recovery accept only complete fenced generations. Volatile
records never mutate a queried HNSW, so a durability fence changes
classification but not query representation.

The mechanism supports a distribution-free strict cap on weak-tail size,
$W\le\lfloor\varepsilon k_{\min}\rfloor$, for minimum weak-visible query width
$k_{\min}$; latest queries below that width are served stable-only. It also
supports exchangeable-mean and hypergeometric policies,
and an online CUSUM guard that fences and falls back to stable ACKs when fresh
records are query-hot. We validate it with 15/15 real process-crash frontiers using
\texttt{\_exit}, 661/661 WAL byte-prefix images, and 2{,}880 query observations
from 240 production-reopened images spanning two HNSW seeds and two recovery
frontiers. Every trial has zero stable-record loss, unexpected weak survivor,
or admission-cap overshoot; all query observations have zero topology
amplification (within $10^{-12}$). Strict observations satisfy
$\Delta^+\le L\le M\le\varepsilon=0.2$. In the post-sync frontier, 60 records
that were weak at crash all survive, producing 90 observations with $L<M$;
strict maxima are $\max\Delta^+=\max L=0.1$ and $\max M=0.2$.

On the canonical Apple-silicon \fullfsync{} run (four writers, 30 image
executions per case), stable group commit has median 279 writes/s
(183--352), while exchangeable random has median 438 (278--552); their observed
ranges overlap. Strict-random has median 175 writes/s (74--251), and the hot
guard has median 113 (79--156). A pre-committer two-host study separately shows
the tax, group-commit curve, and snapshot/WAL recovery gap on Apple and AWS
Linux/NVMe. The committer evaluation is insert-only, single-node, and unfiltered; its Linux
\texttt{dm-log-writes} harness is implemented, but block-replay execution remains
pending suitable disposable hardware.
\end{abstract}

\section{Introduction}
Graph-based ANN indexes---Hierarchical Navigable Small World (HNSW)
graphs~\cite{hnsw} and their descendants---dominate in-memory vector search, and
vector databases built on them now back retrieval-augmented generation and
semantic search at scale. The community evaluates them on \emph{recall@$k$} (the
fraction of a query's true $k$ nearest neighbors the index returns) and
\emph{throughput} (queries/s, QPS), summarized by the recall-vs-QPS Pareto
frontier popularized by ANN-Benchmarks~\cite{annbench} and the Big ANN
challenges~\cite{bigann}. What these evaluations almost never measure is
\emph{durability}: does an acknowledged write survive a crash?

Vector databases now ingest continuously, yet mainstream ANN libraries omit
durable storage (Faiss offers manual serialization~\cite{faiss}; hnswlib has no
crash contract~\cite{hnswlib}), and common benchmarks omit crash recovery and
\fsync{}~\cite{annbench,bigann,vectordbbench}. Production systems such as
Milvus~\cite{milvus} use WALs but publish no isolated durability analysis.
Research systems either inherit a host DB's durability~\cite{cosmos} or, like
LSM-VEC~\cite{lsmvec}, report no synchronization or recovery cost.

We use established storage techniques in a standalone graph-ANN index; group
commit, snapshots, WAL fencing, and the exact-tail composition are not claimed
as novel. Our sole mechanism claim is an opt-in committer that acknowledges
not-yet-durable inserts while enforcing a strict, distribution-free cap on
post-crash top-$k$ loss across every latest-query path, with stable-only fallback
where required, and verifies that contract after production recovery
(\S\ref{sec:recall}). Legacy measurements span Apple and AWS Linux; the
committer experiment uses one Apple host.

\paragraph{Contributions.}
\begin{itemize}
\item \textbf{C1 (\S\ref{sec:honest}).} An implementation and audit of
established crash-consistency techniques on an ANN path, with tmpfs detection,
a sync-floor baseline, and explicit \fsync{}-mode labeling.
\item \textbf{C2 (\S\ref{sec:tax}).} An illustrative pre-committer
mutable-HNSW durability-tax
measurement versus durability strength, with an AWS Linux cross-check.
\item \textbf{C3 (\S\ref{sec:groupcommit}).} A pre-committer mutable-HNSW
group-commit \emph{batch-size sweep}
showing throughput versus batch size and \fsync{} mode.
\item \textbf{C4 (\S\ref{sec:recovery}).} A pre-committer baseline comparing
snapshot load with graph-rebuilding WAL replay on block storage, complementing
P-HNSW's persistent-memory analysis~\cite{phnsw}.
\item \textbf{C5 (\S\ref{sec:recall}).} The sole claimed mechanism novelty:
weak ACKs for not-yet-durable inserts under a strict distribution-free top-$k$
loss cap, enforced across scalar, metadata, and batch latest-query paths and
checked after production recovery. Model-conditional policies and a correlation
guard are evaluated engineering extensions.
\end{itemize}

\section{Background and System}
\label{sec:background}
Our testbed is a from-scratch C++20 vector database with a segmented store. Its
query representation has three layers: immutable sealed HNSW snapshots; a durable
raw delta $R$; and, only when opt-in weak acknowledgment is enabled, a volatile
raw tail $U$. Latest reads search all three layers, stable reads omit $U$, and the
results are merged by the deterministic key $(\mathrm{distance},\mathrm{key})$.
Both raw layers use exact distance scans. In particular, inserting into $U$ and
later hardening it into $R$ never mutates an HNSW. The existing insert API remains
stable-by-default and returns only after synchronization. When recall commit is
enabled, every latest-search API---scalar, metadata, and batch---serves
$k<k_{\min}$ from the stable snapshot and reports the effective visibility on the
structured response. Thus every query that can observe $U$ lies inside the
admission contract.

\paragraph{Durability model.} Version-2 WAL mutation frames contain explicit
lengths, an LSN, operation, payload, and a header-plus-payload CRC. A fence covers
a generation by recording its LSN range, mutation count, rolling hash, and its own
CRC. The sole WAL appender maintains
$\mathrm{appended}\ge\mathrm{visible}\ge\mathrm{durable}$; frame append precedes
in-memory publication internally, while current public status snapshots report
$\mathrm{appended}=\mathrm{visible}\ge\mathrm{durable}$. It reserves LSN ranges
in a CRC-protected high-water file before assignment, so discarded weak-tail LSNs
are never reused. In strong macOS mode, high-water replacement full-syncs the
temporary file, renames it, and then full-syncs the parent directory before the
range becomes assignable; rollover fault injection verifies this ordering and
fails the write before any receipt if the directory barrier fails. Recovery
bounds lengths before allocation, validates mutations
and fences, and accepts only complete fenced generations. Writable recovery
truncates and synchronizes any suffix; the read-only verifier follows the same
parse without modifying the image. Legacy version-1 WALs are treated as stable
and upgraded before weak mode can be enabled. In strong macOS mode, a failed
\fullfsync{} is retried only for interruption and otherwise propagates; it never
downgrades to plain \fsync{}, and a failed fence cannot return a stable ACK.

Sealing is likewise crash-safe: it writes and synchronizes a snapshot plus
\texttt{seal.ready}, creates the replacement mutable generation, atomically
publishes the manifest, and only then retires the old WAL. Failpoints cover each
publication frontier. Recovery of a sealed segment loads its snapshot rather than
rebuilding the graph from its WAL.

\paragraph{Index.} Search uses HNSW with the Malkov--Yashunin diversifying
neighbor-selection heuristic~\cite{hnsw}. The search-time candidate-list width
$\mathrm{ef}$ (and its build-time analogue $\mathrm{ef}_{\mathrm{construction}}$)
trade recall for speed. Distance kernels are SIMD-vectorized (NEON on our host;
an AVX+FMA path is implemented but untested here) with a devirtualized hot path.
Recall@10 on SIFT1M rises with $\mathrm{ef}$ to $0.999$ and is on the same
recall--QPS frontier as hnswlib (Table~\ref{tab:recall}), establishing a
competitive index before durability is added.

\section{Measuring Durability Honestly}
\label{sec:honest}
Durability numbers are worthless without a statement of \emph{what} was made
durable. The pitfalls below are well known in the storage-systems literature---
application-level crash-consistency is hard to get right~\cite{pillai}, commodity
stores mishandle power faults~\cite{torturing}, and even PostgreSQL mishandled
\fsync{} error reporting~\cite{fsyncgate}. Our contribution is not to discover them
but to port this discipline to ANN evaluation, where it is absent. Two traps recur.

\paragraph{The tmpfs trap.} Benchmarks frequently run under \texttt{/tmp}, which
on some Linux distributions is a RAM-backed \texttt{tmpfs}; synchronization there
cannot demonstrate persistence across loss of power. Such an insert benchmark
measures the memory-backed path only. Our
harness \texttt{statfs}-checks the target and \emph{refuses} to report write
numbers on tmpfs.

\paragraph{The \fsync{}-mode trap.} Apple documents that \texttt{fsync}(2) does
not necessarily flush a drive's volatile cache; \texttt{fcntl(F\_FULLFSYNC)} asks
the device to complete that stronger operation. A number labeled
``power-loss durable'' under plain macOS \fsync{} therefore overstates its
contract. Our \emph{sync floor}, a tight \texttt{write()+sync} loop, separates
device synchronization from index work. The $155\times$ mode gap in
Table~\ref{tab:floor} is a macOS/APFS device microbenchmark, not a portable system
speedup; the transferable result is the contract distinction.

\paragraph{Methodology and statistics.} The legacy durability study reports the
median and observed range of seven trials after warm-up; larger-$N$ sweeps and the
extended recovery experiment use three. Seven observations do not justify a
parametric confidence interval, so differences smaller than overlapping ranges
are treated as noise. The committer study is separate: it uses 30 independently
executed tail/write images per case and shuffles case order within each repetition.
Its unit of analysis is an image: recovery queries are averaged within an image,
then min/median/max are reported across images. We do not bootstrap correlated
query rows. The images share one query set and two fixed base graphs (HNSW seeds
100 and 117); each case uses each seed 15 times. Seven cases use a terminal
unfenced-suffix frontier, while strict-hot uses a post-sync/pre-publish process
exit followed by verified resumed work. These are execution repetitions rather
than independent workload or graph samples. SIFT1M recall is one fixed build per index, with single-run query
timing only, so we do not call it deterministic across independently randomized
graph builds.

\paragraph{Cross-platform validation (Linux/NVMe).} To confirm the phenomena are
not macOS artifacts, we ran the legacy suite on an AWS Linux host (x86-64, ext4 on
NVMe), where \fsync{} requests the storage-completion contract used by the
application. The stronger-contract per-write rate is
$378$\,inserts/s (vs.\ the $527$/s floor), group commit yields $4.9\times$
(Table~\ref{tab:gc} shows $4.3\times$ on macOS \fullfsync{}), and the recovery gap
reaches $128\times$ at $N{=}6$k with sealing cost ($29$--$47$\,ms) again far below
the WAL replay it saves ($385$--$4843$\,ms). So the durability tax, the group-commit
curve, and the snapshot-vs-replay recovery result all hold on the platform vector

and process-crash matrix, however, were run only on the Apple host; its physical
block-replay experiment remains pending (\S\ref{sec:threats}).

\section{Pre-Committer Durability Tax}
\label{sec:tax}
We define the \emph{durability tax} as the throughput an index loses and the
latency it adds to guarantee that acknowledged writes survive. We measure it by
inserting one record at a time (each \fsync{}'d before returning) into the
archived pre-committer segmented store, where each mutable insert also mutated
HNSW, and vary \emph{only} the \fsync{} mode. The SIFT-scale configuration uses
$d{=}128$ and $\mathrm{ef}_{\mathrm{construction}}{=}200$. Because the two rows in
Table~\ref{tab:tax} run the identical index work and differ only in whether the
per-insert flush actually reaches the drive, the difference between them isolates
the durability cost for that engine. Since commit \texttt{4017fa7}, the current
engine exact-scans a raw mutable delta and builds HNSW only at seal; current
\texttt{make bench-durability} therefore does not reproduce these rows.

Stronger durability cuts throughput to about a fifth and roughly triples p99.
We do not subtract the single-sync floor: an insert performs multiple durable

\paragraph{Scale checks.} In a three-trial size sweep, the plain-to-\fullfsync{}
throughput ratio falls from $4.5\times$ at $N=2$k to $2.4\times$ at 10k and
$2.1\times$ at 30k as graph work grows relative to fixed synchronization cost;
group-commit benefit falls similarly. The small trial count and wide raw ranges
make this a trend, not a fitted scaling law.

\section{Pre-Committer Group Commit for a Graph-ANN WAL}
\label{sec:groupcommit}
Group commit is a classic database technique~\cite{aether}: batch several log
records and issue a single \fsync{} for the group, decoupling per-operation commit
latency from flush latency. In the archived mutable-HNSW engine, we added a
deferred-sync mode to the mutable segment:
during a batch, WAL appends skip the per-record \fsync{}, and a single
\texttt{commitDeferredSync()} at the end \fsync{}s once for the whole batch. The
then-current public batch-insert path used it; single inserts kept per-write
durability. As in \S\ref{sec:tax}, current raw-delta code has different index work.

\paragraph{Crash scope.} The stable path is exercised inside the committer's
15-frontier \texttt{\_exit} matrix (\S\ref{sec:recall}); the child exits while its
database object is live, and the parent reopens that database through production
recovery. This tests process death and the OS-visible disk image, not loss of
device caches. We implemented a separate Linux \texttt{dm-log-writes} harness that
records an external acknowledgment ledger and replays each block-log entry before
read-only verification. That physical committer-path run has \emph{not} yet been
executed on disposable hardware, so it contributes no result here.

\section{Recall-Bounded Durability}
\label{sec:recall}
Standard group commit does not weaken durability: it releases a group only after
the shared synchronization. Our separate, opt-in weak-ACK API may return after a
complete WAL mutation becomes visible but before a fence is synchronized. Let
$D$ be the total durable population across sealed HNSWs and raw $R$, let
$W=|U|$, and let $k_{\min}$ be the smallest query width allowed to observe $U$.
Latest requests with $k<k_{\min}$ are served from the stable snapshot. For a query
with frozen exact pre-crash top-$k$ set $T$, define
$M=|T\cap U|/k$.

\paragraph{Admission contracts.} Strict admission requires
\[
  W+m\le \lfloor\varepsilon k_{\min}\rfloor
\]
for an atomic request of $m$ records. It is distribution-free; importantly, the
cap is zero when $\varepsilon<1/k_{\min}$, so such a configuration transparently
uses stable group commit. Exchangeable-mean admission instead requires
$(W+m)/(D+W+m)\le\varepsilon$. If insertion order is independent of a query,
$|T\cap U|$ is hypergeometric and $\mathbb{E}[M]=W/(D+W)$. This is a
population-mean model, never a per-query guarantee. A third policy admits only
when the exact hypergeometric tail
\[
 \Pr[\mathrm{Hypergeom}(D+W+m,W+m,k_{\min})>
        \lfloor\varepsilon k_{\min}\rfloor]\le\delta .
\]
The implementation also enforces record, byte, and age limits. If a request does
not fit, it fences the current tail and retries; an indivisible request that still
does not fit receives a stable ACK. No policy silently forces $W\ge1$. Therefore
every servable query that includes weak records has $k\ge k_{\min}$, closing the
otherwise-invalid small-$k$ case.

\paragraph{Commit and query path.} Followers enqueue writes to one leader, which
is the sole WAL appender and serializes admission; concurrent writers therefore
cannot overshoot the cap. A weak insert is released only after its complete frame
and $U$ entry are visible. A stable request, explicit fence, age/size limit, seal,
or shutdown closes the generation; after successful stable synchronization, the
leader atomically advances the durable frontier and reclassifies $U$ into $R$.
The group-delay wait is clipped to the oldest weak record's age deadline, so the
worker begins the age fence before processing queued work; device synchronization
latency remains additive. In requested \fullfsync{} mode, failure is surfaced,
telemetry records no strong-sync success, and the committer enters a failed state
rather than returning Stable after plain \fsync{}.
The vectors remain in the same exact representation. The marginal weak-tail scan
cost is $\Theta(Wd)$, and the total mutable exact scan is
$\Theta((|R|+W)d)$, so weak admission exchanges synchronization work for query
work; it is not free ANN capacity.

Exchangeability is monitored rather than assumed silently. Every latest query
entry point, including segmented batch search,
reports volatile hits to a one-sided CUSUM against the expected hit rate
$W/(D+W)$. An alarm blocks further exchangeable weak admissions, fences the tail,
and serves subsequent weak requests with stable ACKs. This is a drift detector,
not a proof and not retroactive protection; only the configured strict policy is
an adversarial weak-ACK guarantee.

\paragraph{Isolation invariant.} Let $S\subseteq U$ be any records from the
pre-crash volatile tail that are present after recovery, and let the stable
candidate set and deterministic merge be identical before and after recovery.
Because $U$ never mutates an HNSW, the exact membership loss is
\[
 L=\frac{|T\cap(U-S)|}{k}, \qquad
 \Delta^+=\max(0,\mathrm{recall}_{pre}-\mathrm{recall}_{rec})\le L\le M.
\]
We define topology amplification as $\max(0,\Delta^+-L)$. Under isolation, loss
is intentionally independent of HNSW $\mathrm{ef}$: the durable topology and
candidate fingerprint must remain unchanged. The evidence is therefore zero
amplification plus a fingerprint check, not a fabricated $\mathrm{ef}$ effect.

\paragraph{Validation protocol.} Three tests exercise different failure models.
First, the child calls \texttt{\_exit} with a live database at 15 predeclared
admission, fence, and seal frontiers; all 15 read-only verification, writable
reopen, and re-verification cases pass. Second, an exhaustive fixture opens all
661 byte-length prefixes of a
660-byte WAL through the production read-only recovery path; each exposes exactly
the last complete fence and never its weak tail. These are byte-prefix images, not
physical torn-write experiments. Third, the end-to-end benchmark uses two fixed
base graphs (seeds 100 and 117), 160 clustered 12-dimensional base vectors, 25
writes from four concurrent writers, $k=10$, 30 image executions, and 12 recovery
queries for each of eight cases: 240 images, 2{,}880 recovery-query observations,
and 14{,}040 raw operation rows. Each case uses each graph seed 15 times, and case
order is shuffled within each repetition. Seven cases clone a terminal unfenced
suffix. In strict-hot, a child instead records two query-targeted weak records,
calls a fence, and exits at the production post-sync/pre-publish failpoint. The
parent measures immediate recovery, then performs and re-verifies a stable suffix
on a copy, making the crash a nonterminal mid-workload recovery frontier. This
crash/recovery phase is outside the timed writer interval. The data are deliberately
small enough to audit; they are not SIFT1M or a scale result. Hypergeometric
admission is unit-tested but has no performance row in this benchmark.

\paragraph{Results.} Table~\ref{tab:commit} and Fig.~\ref{fig:commitsla} summarize
the canonical run. Every aggregate row has zero stable-record loss, unexpected
weak survivor, cap overshoot, and resumed-suffix failure. All 2{,}880 recovery

fingerprint checks. Amplification is zero within $10^{-12}$ (the only nonzero

and $k=10$, every observation satisfies $\Delta^+\le L\le M\le0.2$. The
terminal strict-random rows have maxima $\max\Delta^+=\max L=\max M=0.1$.
In all 30 strict-hot images, the child records $|U|=2$ before exiting after fence
sync; recovery finds both records ($|S|=2$), so $L=\Delta^+=0$ while
$\max M=0.2$. This yields 90 query observations across 30 images with $L<M$,
60 expected survivors, and 30 stable suffixes verified after writable recovery.
A separate reversed-order base built with seed 1109 is rejected against the
seed-100 configuration on persisted-seed metadata (with no observed answer
drift); normal runs use matching persisted seeds and recovery fingerprints.

The performance tradeoff is large and noisy. Stable group commit's median is
279 writes/s; exchangeable-random's is 438, but their observed ranges
(183--352 and 278--552) overlap. Exchangeable-hot spans 239--533, so the run does
not establish a strict exchangeable-over-stable ordering. Timed synchronization
counts are 7 for stable, 12 for strict, and 2 for unguarded exchangeable rows.
For target $\varepsilon=.05$, random image-mean loss has mean .051, median .050,
and range .017--.083; hot loss is .225 throughout. Exchangeability is therefore
a workload model, not a per-query promise.

Strict mode preserves the distribution-free bound across the full throughput
ranges in Table~\ref{tab:commit}. The hot guard alarms in all 30 images and has
median 113 writes/s while fencing and serving later writes stably; its weak p50
is 4.0\,ms and stable-fallback p50 is 40.6\,ms. Median query p95 is
6.7/6.9\,ms for unguarded exchangeable random/hot and 30.3\,ms with the guard.
These are one-host ranges, not deployment claims. Exact-tail scaling is not
isolated; only its $\Theta(Wd)$ marginal cost is established.

\section{Fast, Crash-Consistent Recovery}
\label{sec:recovery}
The pre-committer stable engine supplies a complementary recovery-cost baseline. A
sealed segment loads an HNSW snapshot, whereas an unsealed legacy mutable segment
replays its WAL through the graph builder. This is distinct from the new
committer's raw $R/U$ recovery path. Table~\ref{tab:recovery} shows that, from
$N=1$k to $6$k, snapshot load rises from 39 to 47\,ms while rebuild rises from

\section{Related Work}
\label{sec:related}
\textbf{Dynamic and durable ANN.} FreshDiskANN~\cite{freshdiskann} and
SPFresh~\cite{spfresh} add streaming graph updates and describe log/snapshot
recovery; LSM-VEC~\cite{lsmvec} distributes a proximity graph across LSM levels.
P-HNSW~\cite{phnsw} compares HNSW WAL replay and snapshot load on persistent
memory. Our legacy measurements instead isolate synchronization cost on block
storage, and our committer asks a different question: which acknowledged records
may be discarded, and what top-$k$ damage can that cause? Manu coordinates
log-publishing writers and subscribing search components through WAL/binlog
backbone services and delta consistency~\cite{manu}; it does not state our
weak-ACK recall-loss contract.

Turbopuffer is the closest operational composition~\cite{turbopuffer}: successful
writes are durably object-stored in a WAL, while committed but not yet indexed
records remain searchable by an exhaustive tail, and a separate system monitors
continuous recall~\cite{turbopufferrecall}. That architecture separates durable
commit from indexing; it does not admit an acknowledged undurable tail under a
recall-loss budget. VStream studies distributed streaming vector search and
the freshness/recall tradeoff~\cite{vstream}; it does not define a storage-failure
loss contract.

\textbf{Bounds and measurement.} TACT~\cite{tact} and Pileus~\cite{pileus} bound
consistency or staleness; PBS bounds replica-version staleness probabilistically
for partial-quorum reads~\cite{pbs}, not membership loss after storage failure.
Aether~\cite{aether} and Silo~\cite{silo} develop logging/group commit.
ANN-Benchmarks~\cite{annbench}, Big ANN~\cite{bigann}, and
VectorDBBench~\cite{vectordbbench} omit crash recovery and synchronization modes.
Against PBS and Turbopuffer, our sole novelty claim is narrower: acknowledge a
not-yet-durable ANN insert only while a strict distribution-free post-crash
top-$k$ loss cap holds on every query path, then verify the contract after
production recovery.

\section{Threats to Validity and Remaining Work}
\label{sec:threats}
The legacy tax/recovery study uses seven trials on Apple and a separate AWS Linux
cross-check; the real committer study uses one Apple M4 Pro and a small clustered
synthetic workload. Thirty tail/write image executions per case expose substantial
timing variance, but they share one query set and only two fixed base graphs. The
terminal frontier is repeated for seven cases; the post-sync/pre-publish frontier
is repeated for strict-hot. These are not independent graph or deployment-workload
samples, and several performance ranges overlap. All pre-crash recall values are 1.0, so
the loss experiment validates membership isolation rather than ANN-error
interaction. There is no controlled query-cost sweep in $W$ or $d$. The legacy
sync-floor loop also omitted syscall return-value accounting, so we use it only to
compare timing under requested sync modes, not to claim observed power survival.

Five implementation threats identified during review are now closed and tested.
Latest scalar, metadata, and batch queries with $k<k_{\min}$ use stable visibility;
every weak-visible batch query feeds the correlation guard; the oldest-tail age
deadline preempts group delay; and failed \fullfsync{} returns an error without a
plain-\fsync{} fallback or stable ACK. Strong-mode atomic replacement now
full-syncs the temporary file, renames it, and only then full-syncs the parent
directory; a reservation-rollover fault test checks descriptor order and
fail-closed behavior. The age deadline determines when fencing starts, not how
long the device takes to complete synchronization. Injected-I/O tests cover these
paths, but not all real-device error and recovery modes.

Strict admission is distribution-free but permits only
$\lfloor\varepsilon k_{\min}\rfloor$ weak records; for common small $k_{\min}$ and
$\varepsilon<1/k_{\min}$, it degenerates correctly to stable commit. Exchangeable mode
can admit more, but hot records violate its mean model, as Table~\ref{tab:commit}
demonstrates. The CUSUM limits future exposure after detection and cannot undo an
already acknowledged tail. In the guard benchmark, image cloning waits for the
alarm-triggered fence, so its zero-loss row does not test a crash during detection
or synchronization. Total mutable search is
$\Theta((|R|+W)d)$. The implementation and evaluation are insert-only,
single-node, and unfiltered; updates/deletes retain stable semantics, and tenant
filters, sharding, and replication remain open.

Finally, 15 \texttt{\_exit} points test process death, 661 byte prefixes test the
WAL parser, and cloned images test production reopen. None removes a device cache
or reproduces arbitrary block persistence. The Linux \texttt{dm-log-writes}
committer harness is implemented with an external ACK ledger, per-entry replay,
normal journal recovery, and read-only verification, but its destructive physical
run is pending suitable hardware. The older graph-rebuild recovery table is a
pre-committer baseline, not a measurement of current raw-delta recovery.

\section{Conclusion}
ANN durability should be reported as a contract, not inferred from an API name.
The two-host legacy study shows why: synchronization semantics change measured
cost, stable group commit recovers much of that cost, and snapshot loading avoids
graph-rebuilding replay. Those are established storage techniques measured on an
ANN path, not new primitives.

The sole claimed novel result is an implemented opt-in path that acknowledges
not-yet-durable inserts only under a strict distribution-free post-crash top-$k$
loss cap enforced across every latest-query path and checked after production
recovery. A sole appender gates $U$, fenced WAL generations define recovery, and
exact $R/U$ layers keep volatile inserts out of HNSW topology. Across 15
process-crash frontiers, 661 WAL prefixes, and 2{,}880 recovered-query observations,
stable records survive, lost IDs stay within $U_{pre}$, admission never overshoots,
and the observed strict rows satisfy $\Delta^+\le L\le M\le\varepsilon$; the
post-sync frontier supplies 60 survivors and 90 observations with $L<M$.
Exchangeable mode is
higher at the median in the canonical run, although its throughput range overlaps
stable group commit, and it fails as a per-query guarantee on hot data. The guard
responds by fencing and falling back to stable ACKs at substantial cost.
The shipped default remains stable. General claims await larger workloads and an
executed physical block-replay experiment.
